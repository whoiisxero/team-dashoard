# Q, Quest's assistant

Q is an original chibi anime companion with fluffy white hair, large blue eyes, rosy cheeks, a tiny blue hoodie and an orange scarf. His limbs animate separately for breathing, waving, blinking, talking and dancing. The chat header and minimised button show his face. He starts at the bottom of the signed-in dashboard and can be dragged anywhere within the visible screen, moved with all four arrow keys (Shift for larger steps), and minimised. Home or **Dock Q** returns him to the corner. Only this public UI placement and minimised preference are stored in local storage; the position is clamped after rotation, resizing and keyboard changes. Reduced-motion settings stop the animations. The panel adapts to phone screens and the height available above a keyboard.

Workspace shortcuts work immediately: My day, direct navigation, reviewed task drafts and dance breaks. Say or type **Q, pull up calendar** to open it immediately, including on a phone. Restricted pages remain restricted. **Add event** starts a separate conversational scheduler. Replies produced by those shortcuts are labelled **Workspace helper**. OpenAI-backed replies are labelled **AI reply**. A missing key is shown as an owner setup requirement, not simulated AI.

## Local personality

Open **✦ Play** for a high-five, spin, stretch or surprise. The same actions work by typing/saying “Q, high five”, “spin around”, “stretch” or “surprise me”. The chat reply includes a small copy of Q so the action is visible on phones where the dock is hidden behind the open panel. Greetings and thanks also get a local response. These gestures do not call an AI provider or start the microphone.

With **Playful reactions** enabled, Q follows the pointer with his eyes on desktop, waves on occasional hover, reacts to being moved and shows a short silent welcome after returning from a hidden tab for at least five minutes. After 90 seconds of inactivity he may stretch, at most once every five minutes. Confirmed completion of a previously loaded task assigned to or created by the member, and a confirmed Q-created calendar event, can trigger a small celebration. Initial task loads and other members’ tasks do not trigger it.

Automatic hints are brief, silent and do not move focus, open a page, send a request or write work. They are suppressed while typing, while a dialog/navigation menu is open, during voice capture/replies, while Q is minimised and while the page is hidden. Only the generic quiet preference is stored as `quest-assistant-playful`; return times, task status snapshots and reaction text stay in memory and reset on account/access changes. The toggle disables automatic reactions; explicit play commands remain available. Reduced-motion settings disable gesture animation and pointer following. Voice recording/transcription now also has distinct listening/thinking poses.

## Enable AI replies

The new Vercel function deploys with the app. In the Vercel project, open **Settings → Environment Variables** and add **OPENAI_API_KEY**, using an API key from your own OpenAI project. Enable it for Production, save, and redeploy the latest deployment so the function receives it. Keep the key out of chat, `config.js` and the repository. OpenAI API usage is billed through that API project.

The default model is `gpt-4.1-mini`. Set **OPENAI_MODEL** on Vercel if a different Responses API model with structured-output support is required. The function reads the existing public Supabase URL/publishable key from the packaged `config.js`. Optional **SUPABASE_URL** and **SUPABASE_PUBLISHABLE_KEY** environment variables can replace them together; no service-role key is used.

After redeploying, open Q and send a workspace question. **AI chat configured** means a key is present; it does not establish that billing, model access or provider availability have been verified. A successful response changes the mode to **AI chat connected** and is marked **Q · AI reply**. A ChatGPT subscription does not configure this API connection or provide API credits.

Q distinguishes insufficient API credits/usage limits, rejected keys, project permissions, unavailable models, request-format errors, rate limits, outages, timeouts and incomplete replies. Setup errors show **AI setup needs attention** while preserving the question. The owner gets a fixed billing/key-management link where appropriate; members get an owner-help message. After activating API billing or adding credits, use **Try again** with the same key. Billing-only changes normally do not require another Vercel redeploy. Key/model environment-variable changes still require redeployment. Raw upstream error messages and API keys are never shown to the browser.

## Permissions and actions

`api/assistant.mjs` authenticates the member's Supabase access token with `/auth/v1/user` and checks current team membership and dashboard access. A POST then fetches a limited context through that same member JWT: accessible projects, assigned unfinished tasks, and upcoming accessible events with explicit time zones. RLS remains authoritative. It does not accept a client-supplied workspace context or use an administrator credential.

A question sends this permitted snapshot and up to six recent chat turns to OpenAI. Private chat bodies, project-note bodies, files, credentials and the membership-management roster are not included. Responses use `store: false`; that setting should not be described as a guarantee about every aspect of provider retention. Conversations remain in the open app's memory and are not written to local storage, a database or offline caches. Changing accounts or project/access scope clears the conversation, draft, speech and outstanding requests.

The model can suggest navigation, dancing, a task draft or an event draft. The server filters unknown/forbidden actions, owner-only pages, inaccessible project IDs and invalid dates. Client checks run again when an action is clicked. Drafts open the existing app editor and require the member to press Save. Task drafts still require review. The separate explicitly requested **Add event** flow saves calendar events automatically once the member supplies the required details. Q does not place trades, send messages/emails, change permissions, delete work or automatically save other kinds of records.

Requests and responses use `no-store`. The endpoint requires membership and bounds input/history/context/output size. It limits requests per member in each warm function instance; that counter is not a durable, distributed quota. Provider project limits remain the place to control total API usage.

## Voice and conversational scheduling

**Mic** requests microphone permission only when tapped. Tap **Stop mic** to transcribe a recording into the question box and review it before Send. For a spoken back-and-forth, enable **Voice conversation** and tap Mic: this also enables **Read replies aloud**, sends transcriptions automatically and listens again after Q finishes a reply. Silence ends a spoken turn when the browser supports audio analysis; Stop mic is also available. **End conversation**, Close, switching accounts, leaving the app and going offline stop capture; late permission grants and transcripts are discarded. No background listening is started on page load or just by enabling the checkbox. Clips are limited to one minute/2 MB. Truncated transcriptions require review.

Reply audio uses device speech synthesis, with a voice selector, a Listen control on each reply and Stop voice. Available voices and automatic playback vary by device/browser. No speech output is cached. HTTPS, a supported MediaRecorder browser and microphone permission are required for input. The same-origin Permissions-Policy allows only this app's microphone; camera and geolocation remain disabled.

`api/transcribe.mjs` checks the same member session before forwarding an in-memory audio clip to OpenAI's Audio Transcriptions API. The default is `gpt-4o-mini-transcribe`; **OPENAI_TRANSCRIPTION_MODEL** may override it with a compatible model. It uses the existing server-only OPENAI_API_KEY, which needs Audio transcription permission as well as Responses permission. Voice clips incur API usage. No clip is written to Quest storage, the database or offline caches; OpenAI's applicable API retention policies still apply.

`api/event-assistant.mjs` uses structured Responses output to collect title, date, time (or explicit all-day), time zone, place, purpose and an accessible project. Relative dates use Africa/Johannesburg unless an explicit event zone is selected. Unknown or invalid details are requested instead of invented. Once complete, it inserts into `calendar_events` using the member JWT and their own `created_by` ID. Place/purpose are stored in the existing notes field; no migration is needed. Standard calendar notification/activity triggers still apply. The app refreshes Calendar, Events and the chat event feed after confirmation. It says “added” only after the database confirms a row.

Each event conversation has a UUID used as the calendar row ID. Retries first read that event under current RLS and recover an existing save; concurrent retries rely on the primary key. A changed account/access scope clears the flow. Cancel before saving adds nothing. A request already saving must finish before cancellation is offered. General chat and model-suggested draft buttons cannot trigger this automatic write path without the explicit event flow.
